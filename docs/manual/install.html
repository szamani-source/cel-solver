Installation

celFoam needs OpenFOAM v2512 from openfoam.com, a C++ compiler and Python 3. On Ubuntu 24.04 the whole setup, from a clean machine to a working solver, takes a few minutes.

1. Get the source

git clone https://github.com/szamani-source/cel-solver.git
cd cel-solver

Without git, download the repository as a ZIP from GitHub (Code → Download ZIP) and unpack it. The rest of this page assumes you are in the repository folder.

2. Install OpenFOAM v2512

Pick one method. Method A is the one this project uses and tests.

Method A: the repository script (recommended)

sudo tools/setup_openfoam.sh

The script installs the same OpenFOAM build that the project's automated tests use, at the standard place, /usr/lib/openfoam/openfoam2512. It downloads the OpenFOAM part of the pinned opencfd/openfoam-dev:2512 container image straight from the registry (no Docker needed), checks every file against its SHA-256 checksum, unpacks it and installs the few Ubuntu libraries it needs. This takes about a minute (66 s for setup, build and tests together in a fresh cloud machine, decision 0007).

  • It is safe to run again: it stops at once if OpenFOAM v2512 is already there.
  • If the registries cannot be reached, it falls back to building OpenFOAM from the SourceForge source tarball, which takes about an hour on 4 cores. Force a method with CEL_OF_METHOD=registry or CEL_OF_METHOD=source.
  • It needs root (it writes to /usr/lib and runs apt-get), plus curl, python3 and tar.

Method B: the openfoam.com packages

OpenCFD publishes Ubuntu packages. Add their repository and install the development package:

curl -s https://dl.openfoam.com/add-debian-repo.sh | sudo bash
sudo apt-get install openfoam2512-dev

This installs to the same path as Method A.

Method C: Docker

Run everything inside the image the project's tests use, with the repository mounted:

docker run -it --rm -v "$PWD":/work -w /work opencfd/openfoam-dev:2512 bash

No root access? Build OpenFOAM v2512 from source in your home folder, following the instructions that come with the OpenFOAM source, and source its etc/bashrc wherever this manual sources /usr/lib/openfoam/openfoam2512/etc/bashrc. celFoam itself never needs root.

3. Load the OpenFOAM environment

Each new terminal needs the OpenFOAM environment before building or running:

source /usr/lib/openfoam/openfoam2512/etc/bashrc

To check it, echo $WM_PROJECT_VERSION should print v2512. You can add the source line to ~/.bashrc, unless you also use another OpenFOAM installation.

Two OpenFOAM versions on one machine. Load only one per terminal. If ~/.bashrc loads another OpenFOAM (for example OpenFOAM 13 from /opt/openfoam13), open a fresh terminal, or remove that line, before loading v2512. Mixing them gives errors such as missing libraries or the wrong blockMesh.

4. Build celFoam

./Allwmake

This builds the four libraries (celConstitutive, celEulerian, celLagrangian, celCoupling), the solver celFoam and the utility celBodyCells. It takes 2 to 4 minutes. The programs go to OpenFOAM's user folders ($FOAM_USER_APPBIN and $FOAM_USER_LIBBIN, under ~/OpenFOAM), which are already on the path once the environment is loaded, so celFoam can be run from any case folder.

Check it:

which celFoam        # prints a path under ~/OpenFOAM/.../bin
celFoam -help        # prints the usage

After pulling new code, run ./Allwmake again; only the changed parts are rebuilt. ./Allwclean removes the build.

5. Test the installation

A quick check (under a second) runs the smallest case:

bash tests/test_smokeBox.sh && echo OK

Two more checks that exercise gravity, walls, the outlet and MPI, about 2 minutes each:

bash tests/test_silo_settle.sh && echo OK
bash tests/test_discharge.sh && echo OK

The full regression suite is

tests/run_tests.sh

It runs every tests/test_*.sh, prints PASS or FAIL for each, and writes each test's output to tests/<name>.log. It takes about three hours on two cores, so it is mainly for developers; the automated checks on GitHub run it for every change.

6. Viewing results

celFoam writes standard OpenFOAM time folders. To open a case in ParaView, create an empty file with the .foam extension in the case and open it:

touch case.foam
paraview case.foam

The fields are described on the quick start page. Each tutorial also has a plot.py that draws its key results with matplotlib (sudo apt-get install python3-matplotlib).

Troubleshooting

MessageCause and fix
wmake: command not found, or WM_PROJECT_DIR: parameter null or not set The OpenFOAM environment is not loaded in this terminal. Run the source line of step 3.
celFoam: command not foundNot built yet, or built in another terminal with a different OpenFOAM loaded. Load v2512 and run ./Allwmake.
Build errors about unknown OpenFOAM classes or headersThe loaded OpenFOAM is not v2512 (check $WM_PROJECT_VERSION).
setup_openfoam.sh: registry ... failed, trying nextThe container registry was not reachable or rate-limited. The script tries the next one, then the source build. A firewall that blocks mirror.gcr.io and registry-1.docker.io leaves only the source build.
ModuleNotFoundError: No module named 'numpy'sudo apt-get install python3-numpy (add python3-matplotlib for the plots).
A parallel run stops with an MPI error about slotsMore processors were asked for than the machine has cores. The tutorials' Allrun scripts already allow this; when you start mpirun by hand, add --oversubscribe (Open MPI), or use fewer processors.
